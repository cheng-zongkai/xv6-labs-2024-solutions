## ❌ 必须修复的严重Bug (3个)

### 1. 数组越界漏洞 ⚠️ 严重
**位置:** `kernel/mmap.c:64`

**问题:** 没有检查VMA数组是否已满就写入
```c
// 当前代码 - 危险！
for(i = 0; i < NELEM(p->vma); i++){
  if(!p->vma[i].len) break;
}
memmove(&p->vma[i], &new_vma, sizeof(struct vma)); // 可能越界！
```

**修复:**
```c
for(i = 0; i < NELEM(p->vma); i++){
  if(!p->vma[i].len) break;
}
if(i >= NELEM(p->vma))
  return -1;  // 添加这个检查
memmove(&p->vma[i], &new_vma, sizeof(struct vma));
```

---

### 2. 长度计算错误 🐛 中等
**位置:** `kernel/trap.c:256`

**问题:** 使用文件偏移量而非VMA偏移量计算剩余长度
```c
// 错误计算
offset = myvma->offset + (va - myvma->addr);
len = myvma->len - offset;  // ❌ 错误！
```

**修复:**
```c
offset = myvma->offset + (va - myvma->addr);
len = myvma->len - (va - myvma->addr);  // ✅ 正确
```

**影响:** 当文件偏移量不为0时，会读取错误数量的数据

---

### 3. panic滥用 ⚠️ 中等
**位置:** `kernel/mmap.c:98, 106`

**问题:** 对用户错误使用panic会导致内核崩溃
```c
// 错误 - 用户错误导致内核崩溃！
if(!myvma){
  panic("munmap: va is not mmapped");
  return -1;
}
```

**修复:**
```c
// 正确 - 返回错误给用户
if(!myvma){
  return -1;
}
```
